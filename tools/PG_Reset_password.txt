## Diagnosi

La causa è il segreto `APP_URL` della Edge Function `request-password-recovery` sul progetto staging (`ompjckjbvauemoxwggdi`), che è impostato su `http://localhost:3000`.

Conferma nel codice: `supabase/functions/request-password-recovery/index.ts:50,93-95` costruisce `redirectTo = APP_URL + "/auth/recovery"`, e `APP_URL` viene letto da `Deno.env.get("APP_URL")` (il segreto esiste su staging, impostato il 2026-07-17). L'email ricevuta contiene esattamente `redirect_to=http://localhost:3000/auth/recovery`.

Effetto: il link rimanda a un host loopback, non a `https://web-gdr-staging.vercel.app`; il client su `localhost:3000` non è il SPA staging (seleziona la config di produzione) e il token OTP dello staging non viene mai validato → dopo il primo caricamento il link dà `otp_expired`/`access_denied` (il token recovery è monouso, quindi anche ricaricando resta quell'errore).

Il lato client (`session.js:243-288`, `router.js:320-322`, `auth.js:123-146`) è già corretto: appena il link punta allo staging, `detectSessionInUrl` + `PASSWORD_RECOVERY`/`isPasswordRecoveryFlow` mostrano "Imposta nuova password". `vercel.json` riscrive `/auth/recovery` su `index.html`. Non serve toccare codice.

## Piano di fix

1. **Correggere il segreto `APP_URL` su staging:**
   - `supabase secrets set APP_URL=https://web-gdr-staging.vercel.app --project-ref ompjckjbvauemoxwggdi`

2. **Ridistribuire la Function:**
   - `supabase functions deploy request-password-recovery --project-ref ompjckjbvauemoxwggdi`

3. **Verificare/correggere la configurazione Auth dello staging** (Dashboard → Authentication → URL Configuration, oppure API di gestione `GET/PATCH /v1/projects/{ref}/config/auth`):
   - Site URL = `https://web-gdr-staging.vercel.app`
   - Redirect URLs consentiti: `https://web-gdr-staging.vercel.app` e `https://web-gdr-staging-*.vercel.app` (preview). Senza questo, GoTrue può scartare/ignorare `redirect_to` anche con il segreto giusto.

4. **Ritestare su staging:** nuova richiesta di recovery → il link nell'email deve contenere `redirect_to=https://web-gdr-staging.vercel.app/auth/recovery` → la pagina staging mostra il form e il cambio password va a buon fine.
